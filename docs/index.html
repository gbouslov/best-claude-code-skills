Claude Code skills examples and best practices

For a small workflow of your own, create .claude/skills/review-change/SKILL.md in the project:

---
name: review-change
description: Review a proposed change against its acceptance criteria before merging.
---

Read the acceptance criteria and changed files within the current repository.
Explain which criteria the change satisfies, identify missing checks, and
suggest the next verification. Report findings without editing files or
running deployment commands.

Invoke it with /review-change. Make the description specific, keep long references in supporting files, and check the workflow on realistic tasks. Compare its results with and without the skill before relying on it; the official evaluation guide describes that process. The Claude Code skills guide covers frontmatter and invocation controls.

Install and list Claude Code skills

Follow the linked project's setup instructions. Repositories distribute skills in different ways: some are plugin marketplaces, some support the skills CLI, and some document copying an individual folder.

For Anthropic's document skills, run these commands inside Claude Code:

/plugin marketplace add anthropics/skills
/plugin install document-skills@anthropic-agent-skills

For a skill you author or copy manually, the project location is .claude/skills/<skill-name>/SKILL.md; the personal location is ~/.claude/skills/<skill-name>/SKILL.md. Project scope makes a shared workflow travel with the repository. Personal scope makes it available across your projects. The official skills documentation explains discovery, invocation and configuration.

Read the instructions and accompanying scripts before enabling a third-party skill. For a shared workflow, keep the chosen version and setup instructions with the project. Contributions should link directly to the project's current installation instructions.

List available and installed skills

In current Claude Code, open /skills to manage skill visibility, or type / to browse invocable skills and commands. Ask What skills are available? to see what the session can discover. Plugin-provided skills are managed through /plugin; the current skills guide explains the difference.

If you installed through the separate skills CLI, npx skills list lists that installer's local skills and npx skills list -g lists global ones. Those commands are for the installer; they are not Claude Code built-in slash commands. See the skills CLI reference.

Troubleshooting skill discovery and listing limits

If a skill does not appear, check its SKILL.md location, frontmatter and the active project directory. A repository containing a nested skills/ folder is not always installable by cloning its root into your personal skills folder: use its documented route. Invoke /skill-name directly when it is user-invocable.

If you see “skill listing will be truncated,” inspect /context and /doctor. The listing budget can shorten descriptions even when names remain visible; the current settings include skillListingBudgetFraction and the fixed-character SLASH_COMMAND_TOOL_CHAR_BUDGET override. Review the official listing-limit guidance before changing them. /skill-doctor can identify unused skills on supported versions.

For a todo-list skill, start with Planning with Files when you want a persistent plan and progress files. For normal issue tracking, Matt Pocock's setup and triage skills connect the workflow to your chosen tracker. Pick according to where you want tasks to live.

Alternatives and other skill directories

For a one-off instruction, a normal prompt may be enough. Put persistent project context in CLAUDE.md, use a hook for a deterministic event check, and use a connector when the missing capability is service access. The Claude Code features guide explains when these mechanisms fit.

For GitHub Copilot, the official skills setup guide supports project skills in .github/skills/, .claude/skills/ or .agents/skills/; personal skills use ~/.copilot/skills/ or ~/.agents/skills/. The shared SKILL.md format can travel between hosts, but Claude-specific hooks, tools and plugin setup still need the target host's documented equivalents. Check the collection's Codex, Cursor or Copilot route before copying a whole bundle.

For more breadth, browse Awesome Claude Skills, Composio's Awesome Claude Skills and Awesome Claude Code. Reddit discussions can supply practitioner examples; use the linked primary repositories here to check current setup, licenses and dependencies before installing a recommendation.

Frequently asked questions

What are Claude Code skills?

Skills package reusable task instructions in a folder containing SKILL.md, with optional scripts and reference files. Claude Code can load an applicable skill or invoke it by name. See the official guide.

What are Claude Code plugins vs skills?

A skill teaches a workflow; a plugin can distribute it alongside commands, hooks and agents. An MCP server connects the agent to tools or data, so a workflow may need both a skill and a connector.

What are the best Claude Code skills?

Pick the row for your next task. For documents, start with Anthropic; for React performance, Vercel; for an Expo app, Expo; for requirements discussion, Matt Pocock. Add another collection when you have a task it covers.

Can Claude Code skills be used in Codex?

The Agent Skills format is shared across participating tools. Check the project's instructions for your agent: host-specific hooks, commands and connectors can require different setup.

Are Claude Code skills free?

Check the specific upstream license: Anthropic's document skills are source-available, while other examples use open-source licenses. A free download can still require a paid model, service or compute. The MIT license here covers this list's original text; linked projects retain their own terms.

How to install Claude Code skills from GitHub?

Open the repository's current setup guide and use its documented plugin, skills-CLI or manual-folder route. The install table above gives focused examples; a GitHub repository can contain several skills and optional components.

How to install Claude Code skills globally?

Manual personal skills live in ~/.claude/skills/<skill-name>/SKILL.md; supported installers also offer a global option. Check the project's command and installer prompts so you install for Claude Code and the scope you intend.

How to list all skills in Claude Code?

Open /skills in current Claude Code and ask What skills are available? to inspect session discovery. The / menu shows invocable commands; plugin skills and installer inventories are covered in the install-and-list section above.

Where are Claude Code skills stored?

Project skills live under .claude/skills/ and personal skills under ~/.claude/skills/. Plugin and managed sources have their own loading rules, so use the official locations guide when a skill comes from another source.

Does Claude Code use skills automatically?

Claude can load relevant skills from their descriptions, and you can invoke user-invocable skills with /skill-name. A skill with disable-model-invocation: true requires manual invocation; see the invocation controls.
